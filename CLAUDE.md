# Weg — rules for every agent

Weg is a free Windows desktop app that takes an international student in Germany from A1.1 to C1.2 German. Read these before any work:

- `docs/north-star.md` — what the finished app is. **When it disagrees with the code or with this file, the north star wins** until LuisFe changes it.
- `docs/build-plan.md` — who builds what, and what to reuse instead of building.
- `docs/ARCHITECTURE.md` and `docs/adr/` — where each part lives and why.

## Stack

| Part | Choice |
| --- | --- |
| Shell | Tauri 2 (Rust core, WebView2), Windows 11 first |
| UI | React 19, TypeScript (strict), Vite, Tailwind CSS 4, shadcn/ui |
| Learner data | SQLite through `tauri-plugin-sql`, migrations in `src-tauri/migrations/` |
| Scheduler | `ts-fsrs` |
| AI | `openai` npm client behind the AI gateway; any OpenAI-compatible provider |
| Speech | sherpa-onnx in the Rust core; models downloaded on first use |
| Grammar check | LanguageTool |
| Tests | Vitest + Testing Library (TypeScript), `cargo test` (Rust) |
| Lint | ESLint (flat config), `cargo clippy` |
| Content | JSON validated by the JSON Schemas in `schemas/` |

## Folder layout

```
curriculum/        one JSON file per sublevel, <id>.json
gold/              gold test bank (JSON Lines); never shipped in the app
prompts/           one Markdown file per AI role, versioned
evals/             eval runner, model list, scoreboard
schemas/           JSON Schemas; fixtures in schemas/examples/
scripts/           Node scripts (validation, build-time data slicing)
src/screens/       the seven screens
src/components/    shared components; components/ui/ is generated by shadcn, do not hand-edit
src/engine/        learning logic: pure TypeScript, no I/O, no React
src/ports/         interfaces the engine depends on
src/adapters/      implementations of the ports (Tauri, SQLite, AI, speech)
src/content/       loaders and types for curriculum/
src/lib/           small utilities (sanitize.ts, db.ts, utils.ts)
src-tauri/         Rust core, migrations/, capabilities/
docs/              north star, build plan, architecture, adr/
.claude/agents/    subagent definitions
```

Dependencies point one way: screens → engine → ports ← adapters. The engine never imports React, Tauri or an adapter.

## Coding rules

1. **Small pull requests.** One issue, one branch, one PR. Never commit to `main`.
2. **Engine code is pure.** No `Date.now()`, `Math.random()`, `fetch`, SQL or Tauri calls in `src/engine/`. Time comes from a `Clock` port, randomness from a seed.
3. **No learning rule in a prompt alone.** If the north star states a number or a rule (95% coverage, three errors at most, 90% hours before a gate), code checks it.
4. **TypeScript strict; no `any`, no `@ts-ignore`.** Validate data at the boundary (AI output, files, database rows) and trust types inside.
5. **Rust stays thin:** I/O and native libraries only. No `unwrap()` on anything that can fail at run time; return errors to the UI.
6. **Reuse before building.** Check build-plan section 2. A new dependency needs a reason in the PR and a licence on the allow-list.
7. **Content is data.** Nothing about a sublevel, a word or a grammar point is written in code. Content strings are plain text: no Markdown, no HTML.
8. **Migrations are append-only.** Never edit a migration that has been merged; add the next one.
9. **UI:** calm and plain. One accent colour, large type for German text, every screen usable by keyboard. No streaks, XP, badges, mascots or celebratory animation, ever.
10. **Explanations in English and Spanish; practice in German.** Every learner-facing explanation string exists in both `en` and `es`.
11. **Write for the next agent.** Comment why, not what. If a file needs a paragraph to explain, it is too big.
12. **Honest claims.** The app never states an official CEFR level, and a gate result is always called a practice score.

## Test rules

- Every engine module has unit tests; a PR that adds or changes engine logic without tests is rejected.
- A bug fix starts with a test that fails.
- Tests are deterministic: fixed clock, fixed seed, no network. AI and speech are faked at the port.
- Screens get a render test for their main state and their failure state.
- Content changes must pass `npm run validate`. A schema change updates the fixtures in `schemas/examples/` in the same PR, including an invalid fixture for each new rule.
- A change to a prompt or to the model list re-runs the evals for that role; the scoreboard is committed with the change. **A change that puts a role below its bar is not merged**, even if every code test passes.
- Never weaken, skip or delete a test to make a change pass. If a test is wrong, say why in the PR.

## Licence allow-list

Hard rule 2 of the north star. Anything not listed here needs a written decision from LuisFe before it enters the repo, the installer or a download list.

| Kind | Allowed | Not allowed |
| --- | --- | --- |
| Code dependencies | MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, 0BSD, Zlib, Unicode-3.0, MPL-2.0 (unmodified, as a dependency), LGPL (libraries, dynamically linked or as a separate service), CC0, public domain | GPL, AGPL, SSPL, BUSL, any "non-commercial" or "research only" licence, unlicensed code |
| Content and datasets | Original work, CC0, CC BY, CC BY-SA (kept separable from the MIT code and attributed) | CC BY-NC, CC BY-ND, anything copyrighted without a licence |
| Voices and models | Only those whose model card states a licence from the rows above, for the weights **and** the training data terms | XTTS-v2; any voice or model with non-commercial terms |

Specific sources:

- **Never copied, only linked or used to cross-check:** Goethe-Institut and telc material and word lists, Profile Deutsch, DW (Nicos Weg), textbooks, Easy German.
- **GPL projects (LinguaCafe, Lute):** study the idea, never read code into this repo.
- **Deutsch im Blick** (CC BY 4.0): adapt with attribution; check each video's own licence.
- **Tatoeba:** sentence text is CC BY 2.0 FR; audio is licensed per clip, so check each one.
- **Wiktionary / kaikki.org** (CC BY-SA): build-time slices only, attributed, stored as data files apart from code.
- Every non-original content item records `source` and `licence` in its JSON.

## Security rules

1. **Sanitise all AI output.** Every string from an AI provider, a speech recogniser or LanguageTool passes through `sanitizeAiText` (`src/lib/sanitize.ts`) in the adapter, before it is stored or shown. Treat it as untrusted plain text, always.
2. **Never inject HTML.** No `dangerouslySetInnerHTML`, `innerHTML`, `eval` or `new Function`. Lint enforces this; do not disable the rule. HTML sinks outside React (Anki export) use `escapeHtml`.
3. **AI output never becomes an instruction.** It is not used as a file path, URL, SQL fragment, shell argument or command name. It is parsed as JSON against a schema, or shown as text.
4. **No secrets in the repo.** API keys live in the Windows Credential Manager through the Rust core. `.env` is for local development and evals, is git-ignored, and is never read by the app. Never log a key or put one in a URL.
5. **Keys never enter the WebView.** Provider calls go through the Rust command that adds the key (ADR 0003).
6. **Keep the CSP strict.** Do not add hosts to `connect-src` or `'unsafe-inline'` to `script-src` in `tauri.conf.json`.
7. **Least privilege.** Add a Tauri capability only for the command a ticket needs. No shell plugin, no broad file-system scope.
8. **SQL parameters are always bound.** Never build SQL by joining strings.
9. **Local data stays local.** No telemetry, analytics, crash upload or account. The only network calls are to the AI provider the learner chose, LanguageTool, Azure with the learner's own key, and model downloads. A new destination needs a written decision.
10. **Downloads are verified.** A model or voice is fetched over HTTPS from a pinned URL and checked against a checksum in the repo.

## Never

- **Never add a Python runtime or a bundled LLM to the installer.** Heavy models are optional downloads on first use. Build-time and validation scripts are Node.
- Never add payments, ads, subscriptions, accounts, sync or telemetry.
- Never add streaks, XP, leagues, hearts or any other game mechanic.
- Never use the Claude subscription token, or any key of LuisFe's, inside the app or for its users.
- Never let a gate be skipped, or passed on a low-confidence score.
- Never approve your own change. The agent that wrote the code does not review it.

## Agents

Five subagents live in `.claude/agents/`:

| Agent | Does | Edits |
| --- | --- | --- |
| `curriculum-writer` | Writes sublevel specs and gold-bank content | `curriculum/`, `gold/` |
| `content-validator` | Checks content against schemas, progression and licences | Nothing; reports |
| `builder` | Implements one issue with tests | Code |
| `eval-runner` | Runs the AI evals and updates the scoreboard | `evals/` results only |
| `reviewer` | Reviews a change against this file | Nothing; reports |

## Git

- Branch names: `<issue number>-<short-slug>`. Commit messages: imperative, one line, then why if it is not obvious.
- `npm run check` passes before every commit. CI runs the same checks plus the Windows build.
- Do not commit generated folders (`dist/`, `src-tauri/target/`, `src-tauri/gen/schemas/`), model files or recordings.
